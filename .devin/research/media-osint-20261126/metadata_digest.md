What we cover in this video

Why motion with Claude burns your usage
- One-prompt AI video projects can use up a whole usage limit; one person had their agent working on a single video for 12 hours straight
- Someone said one video used 35% of their weekly usage limit
- Most of that usage goes into the agent redoing work it already finished
- Two causes: the agent starts with an unclear idea, and every change sends it back through the whole process

Model and effort settings in Claude Code
- Pick Opus with the model command; Fable gets even better results but uses a lot more of your usage
- Opus defaults to medium effort, which already works well; high and extra high give a better video but hit your limits faster
- We used high, since that's what we use for creative and visual work

Step 1: The video brief skill
- Build Claude motion with a reusable workflow instead of one giant prompt, starting with a skill that writes a VIDEO.md plan
- Three modes: detailed (lots of questions, good if you have brand rules), general direction (fewer questions, Claude fills in the rest), or Claude makes every decision itself
- A brief for Claude: graphics, motion, music, length and orientation, all settled before anything gets built
- Makes two or three visual ideas so you can see what it means instead of only reading the file
- Every motion video Claude builds starts from VIDEO.md, so a fresh session can pick it up without asking you anything else

The banned slop patterns skill
- A list of everything that shows up when you ask an agent for a video without much direction, like tiny labels in the corner or fake timecodes
- Covers how each shot is laid out and how things move from one shot to the next
- Used every time the agent plans, builds or checks a video, so your Claude motion graphics don't look like generic AI video

Step 2: The video build skill
- The motion graphics Claude builds are written as code; the skill never renders the video itself
- Comes with sample templates, build scripts, notes on the code libraries it uses, strict rules and a step-by-step process
- You only turn it into a real video file once you've checked everything, which saves time and tokens

Step 3: The video fixer agent and video review skill
- A custom fixer agent running on Sonnet handles small changes like text or timing, and can't redesign the video or change its creative choices
- The review skill plays the code itself in a viewer in your browser, so there's no render to wait for
- It makes a contact sheet, one image with a small picture from every second, and checks the whole video in one go
- Video editing by notes: leave comments on the exact second you mean, send them all together, and the skill sorts them by scene
- Small notes go to the fixer agent all at once, and the main model only handles the bigger design changes

Making a Claude video from start to finish
- Start with the video brief slash command; we used general direction mode for an AirPods demo in the style of an Apple product demo
- Claude AI asked what the video was about, who it was for, the look, the length, the orientation and which features to show
- Close the planning session once VIDEO.md is written; with the plan in motion, Claude builds it in a new session with a clean context
- Our build took around 41 minutes because the AirPods model was made completely in code
- Review the video motion Claude built in your browser, click Send Notes for the fixes, then Approve and Render for the final file
- The finished video: Claude motion graphics with music, shown in full at the end

- Every skill we built is available in AI Labs Pro, our community (link above)
- Every prompt we used is shown on screen, so you can pause, copy it and give it to your own agent
